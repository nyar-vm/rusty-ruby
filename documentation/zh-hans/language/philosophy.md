# 设计哲学与核心理念

RBQ (Rusty Brief Query) 不仅仅是一个数据库驱动或 ORM，它是一个**统一的数据库执行与建模层**。其设计旨在平衡工业级的稳定性与极致的开发灵活性。

## 1. 核心愿景

**建立 Rust 生态中统一、稳定、高性能的数据库执行与建模层。**

RBQ 将声明式建模语言（RBQ Language）与物理执行引擎（RBQ Core）深度集成，提供从数据定义到高效执行的一站式解决方案。

## 2. 设计原则

### 2.1 建模与执行一体化
RBQ 引擎同时负责“表达意图”（RBQ Language）和“物理执行”（RBQ Core）。这种集成允许编译器在了解物理特性的基础上，对逻辑查询进行深度优化。

### 2.2 声明式优于命令式
在 RBQ 中，你描述数据模型“是什么”以及你想要“什么数据”，而不是描述“如何去获取数据”。编译器负责将这些声明转换为最优的物理执行计划。

### 2.3 三层 IR 架构
为了确保查询转换的可观测性与灵活性，RBQ 编译器采用了三层中间表示（IR）：
*   **HIR (High-level IR)**：高级语义层。负责类型检查、宏展开、`micro` 函数内联以及语法糖脱糖。
*   **MIR (Middle IR)**：逻辑执行计划层。负责查询优化、关系解析以及方言无关的逻辑映射。
*   **LIR (Low-level IR)**：物理执行计划层。根据目标数据库生成特定方言的 SQL 或 API 调用。

### 2.4 尊重协议差异
RBQ 并不试图完全屏蔽底层数据库的特性。相反，它通过统一的 API 暴露这些特性，并利用驱动层（We-Trust 协议）处理具体的协议细节，确保在不同后端上都能发挥最大性能。

## 3. 视觉美学：赛博商务 (Cyber-Commercial)

RBQ 的界面与输出设计遵循“赛博商务”理念：
*   **极简实用**：界面服务于逻辑，减少视觉噪音。
*   **高对比度**：关键操作与报错信息清晰可见。
*   **工业级诊断**：参考 `rustc` 风格，提供结构化的错误反馈，包括错误代码、诊断建议和代码快照。

## 4. 核心优势

*   **开发者掌控感**：让开发者感受到“掌握底层数据流”的掌控感。
*   **端到端优化**：从 .rbq 文件到二进制传输协议的零开销抽象。
*   **生态标准化**：通过 We-Trust 协议抹平驱动层差异，建立生产级标准。
