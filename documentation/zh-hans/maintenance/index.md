## 维护目标

1. **类型一致性**：确保所有驱动后端对 RBQ 标量类型的支持是一致的。
2. **性能基准**：监控 HIR 到 LIR 的转换效率，优化物理执行计划生成。
3. **方言覆盖**：持续增强对主流数据库（PostgreSQL, MySQL, SQLite, Redis）新特性的支持。
4. **xRPC 实现**：确保 RPC 服务的高性能和可靠性。

## 架构概览

RBQ 的架构设计遵循清晰的分层原则：

1. **DSL 层**：使用 `.rbq` 文件定义数据模型和 RPC 服务。
2. **编译器层**：将 DSL 转换为高性能的 Rust 代码，包含 ORM 和 RPC 功能。
3. **运行时层**：提供数据库连接、事务管理和 RPC 服务运行时。
4. **驱动层**：适配不同的数据库系统，处理方言差异。

## 贡献指南

1. **代码风格**：遵循 Rust 官方代码风格指南。
2. **测试覆盖**：确保所有新功能都有相应的测试用例。
3. **文档更新**：同步更新相关文档，确保文档与代码保持一致。
4. **性能考虑**：关注编译期和运行期性能，避免不必要的开销。
