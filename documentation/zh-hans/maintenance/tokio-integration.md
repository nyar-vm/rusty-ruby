# 深度适配 Tokio 生态的设计说明

RBQ (Rust Business Query) 选择了深度适配 **Tokio** 生态，而不是追求运行时无关性。以下是这一决策的核心原因及技术优势。

## 1. 追求极致性能
Tokio 是 Rust 异步生态中性能最强、应用最广的运行时。
- **多线程调度**：利用 Tokio 的工作窃取（Work-stealing）调度器，RBQ 能够高效处理成千上万个并发数据库连接。
- **IO 吞吐量**：通过 `tokio-util` 的 `codec` 抽象（`Framed` / `Decoder` / `Encoder`），我们将协议解析与底层网络 IO 分离。这允许驱动程序以零拷贝或极低拷贝的方式处理二进制协议，显著提升了吞吐量。

## 2. 现代 IO 模式：流式处理 (Streaming)
在 Tokio 生态中，流式处理是处理大数据的标准方式。
- RBQ 实现了 `query_stream` 接口，允许应用以 `Stream` 的形式逐步消费查询结果，而无需将整个结果集一次性加载到内存中。这对于内存受限或处理海量数据的场景至关重要。

## 3. 生态协同与兼容性
Rust 的高性能异步库（如 `sqlx`, `tower`, `axum`, `tonic`）大多原生适配 Tokio。
- **无缝集成**：深度集成 Tokio 意味着 RBQ 可以直接利用这些成熟库提供的功能（如 TLS 支持、高级限流等）。
- **降低心智负担**：开发者无需在不同运行时的兼容层之间跳转，代码更加纯粹且易于调试。

## 4. 稳健的资源管理
利用 Tokio 提供的原语，RBQ 实现了更加健壮的连接池管理：
- **异步信号量**：使用 `tokio::sync::Semaphore` 精确控制最大并发连接数。
- **后台维护任务**：利用 `tokio::spawn` 和 `tokio::time::interval` 自动执行连接池的健康检查、过期清理和热备维护。

## 5. 结论
通过深度适配 Tokio，RBQ 能够为开发者提供一个**高性能、低延迟、且高度可预测**的数据库访问层。我们相信，在现代云原生应用开发中，选择最成熟的生态系统是实现生产级稳定性的最佳途径。
